## 0. 결정됨 — 오답 원인은 AI가 진단한다

**2026-07-30 결정.** 2026-07-29에 보류했던 갈림길이다. `PRD-002 오답 원인 태깅`을 쓰다 나왔고, 기능 하나가 아니라 **제품의 성격을 정하는 문제**라 여기 남겼다.

**세 갈래 중 「AI 도입」을 택했다.** 헌법 원칙 I이 v2.0.0(오답 원인 진단)과 v3.0.0(PDF 문항 분석)에 걸쳐 두 번 재정의되면서 확정됐다.

당시 정리했던 갈래와 그 결말이다.

| 갈래 | 얻는 것 | 잃는 것 | 결말 |
|---|---|---|---|
| 로컬 손글씨 인식 | 외부 의존 0 유지. 데이터가 기기 밖으로 안 나감 | 난이도가 크다. 정수 인식과 "왜 틀렸는지 추론"은 다른 일이다 | 미채택 |
| **AI 도입** | 진단 품질 | 프록시 서버·미성년자 데이터 동의·오프라인 대응이 연쇄로 붙는다 | **채택** |
| 자가진단 유지 | 지금 당장 만들 수 있다 | 학생이 스스로 판단해야 한다 | 미채택 (단 `selfCause`는 남는다 — 아래) |

**"잃는 것"은 실제로 청구서가 됐다.** 세 항목 전부 헌법에 조항으로 들어갔다.

- 프록시 서버 → 원칙 I. **아직 없다. AI 기능 전체의 선행 조건이다** (§11 참조)
- 미성년자 데이터 동의 → 「데이터와 프라이버시」. 항목 단위 열거 + 명시적 동의가 MUST
- 오프라인 대응 → 원칙 I. 이미 분석된 문항의 채점은 오프라인 동작 보장

**`design-system/README.md` 원칙 3과의 긴장은 경계를 그어 해소했다.** 그 원칙은 *"검증 가능한 것은 도구가 판정하고, AI는 그 위에서 설명만 한다"* 인데, 여기 *"원인 진단은 설명이 아니라 판정에 가깝다"* 고 적어뒀었다. 헌법 원칙 II가 그 선을 명시했다 — **채점(O/X)은 도구의 판정, 원인은 AI의 의견.** AI는 판정을 만들거나 뒤집을 수 없고, 학생의 자가진단보다 먼저 노출될 수 없다. 그래서 자가진단(`selfCause`)은 폐기되지 않고 AI 진단(`aiCause`)과 대조되는 형태로 남는다.

→ `PRD-002` 보류 사유가 소멸했다. 재개 가능하다.

## 12. 구현 순서 제안

1일차에 스파이크를 먼저 돌린다. 여기서 `pressure`가 실패하면 이후 순서가 바뀐다.

| 순서 | 작업 | 근거 |
|---|---|---|
| 1 | 실기기 필기 스파이크 | 유일하게 설계를 뒤집을 수 있는 미지수 |
| 2 | `segment.ts`에 `choices[]` 추가 + 테스트 | 채점의 전제. 순수 함수라 기기 없이 가능 |
| 3 | PDF 렌더 + 필기 캔버스 + 귀속 | 가장 큰 덩어리 |
| 4 | 저장·재진입 | 여기까지가 "도구"로서 성립하는 최소 |
| 5 | 정답 파싱 + 정답 입력 화면 | |
| 6 | 채점 + 결과 표시 | |
| 7 | 다시 풀기 + 회차 레이어 | |
