### 상태 — 가장 많이 빠뜨리고, 개발 막판을 지옥으로 만드는 원인 1위

| 화면 | 정상 | 로딩 | 빈 상태 | 에러 |
|---|---|---|---|---|
| S-1xx | | | | (SDD-00X E1) |

보통 정상만 만든다. 그런데 실제로는 — 처음 설치한 학생은 문서가 0개라 **화면이 텅 비고**,
PDF가 깨지면 **아무 반응이 없어** 학생은 계속 탭만 누른다. 개발 다 끝나고 발견하면
컴포넌트 구조를 뜯어고쳐야 한다.

**`해당 없음`도 정보다.** "확인했고 필요 없다"와 "생각 안 해봤다"는 다르다. 빈칸으로 두지 않는다.

### 에러 배치 검증

위 `에러 처리`의 `E1`~`EN`을 **하나도 빠짐없이** 어느 화면이 보여줄지 정한다.
표기는 반드시 `(SDD-00X E1)` 형식 — `docs/check-errors.sh`가 이 문자열을 찾는다.

    sh docs/check-errors.sh

어느 화면에도 안 붙는 에러가 있으면 둘 중 하나다.

- 화면이 빠졌다 → 표에 추가
- 사용자에게 안 보여도 된다 → **`에러 처리` 표에 그렇게 적는다** (`로그만, 화면 표시 없음`).
  조용히 넘어가지 않는다
