## 그리고 코드를 본다 — 이 저장소는 브라운필드다

코드가 문서보다 앞서 있다. 읽지 않고 쓰면 **이미 되어 있는 걸 "만들자"고 정하게 된다.**

    grep -rn "<기능 관련 심볼>" --include="*.ts" --include="*.tsx" apps/student-mobile/src

| 분류 | 뜻 | 할 일 |
|---|---|---|
| 이미 됨 | 로직·UI·테스트가 다 있다 | 범위에서 뺀다. 사용자 인식과 다르면 **증거를 보여주고 다시 묻는다** |
| 만들다 만 것 | 컴포넌트는 있는데 어느 화면도 안 쓴다 | 멈춘 구상의 흔적. 이번 spec이 그걸 완성하는 건지 확인 |
| 없음 | 흔적이 없다 | 진짜 새로 만드는 것 |

**사용자의 현재 상태 인식이 코드와 다르면, 코드가 사실이다.**

## 절대 규칙

1. **추측 금지.** 정보가 없으면 지어내지 말고 `[NEEDS CLARIFICATION: 무엇을 모르는지]`로
   표시한다. 모르는 걸 모른다고 적은 spec이 그럴듯하게 지어낸 spec보다 낫다.
2. **구현 수단 금지.** "겹침 25% 이상"은 plan.md 소관. 여기엔 **학생이 무엇을 얻는지**만 —
   가르는 기준은 *학생이 겪는 것인가, 구현자가 지키는 것인가*. 숫자 유무로 가르지 않는다.
3. **측정 불가 형용사 금지.** "빠른", "쉬운", "좋은" — 숫자로 바꾸거나 지운다.
4. **모순은 즉시 지적한다.** 앞뒤 다른 말이 나오면 넘어가지 말고 그 자리에서 확인한다.
5. **약어는 처음 나올 때 풀어 쓴다.** `MVP(원어: Minimum Viable Product, 최소 기능 제품)`

## 여기 쓰지 않는 것 — 쓰면 이중 관리가 된다

| 화면 구성·레이아웃·색 | `docs/screens/`, `screen-composer` 에이전트 |
| 판정 규칙·임계값·알고리즘 | plan.md (`/speckit-plan`) |

**분량은 A4 한 장.** 넘으면 다른 문서 내용이 섞인 것이다.
