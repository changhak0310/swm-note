# Phase 0 Research: AI 기반 PDF 문항 분석

**Date**: 2026-07-31 · **Plan**: [plan.md](./plan.md)

Technical Context의 미상 항목과 AI 연동 설계 선택을 여기서 해소한다. 확정할 수 없는 값은
헌법 원칙 III에 따라 **지어내지 않고** plan의 Unresolved로 넘겼다.

---

## D-1. 모델

**Decision**: `claude-opus-5`

**Rationale**: 이 작업은 조판이 제각각인 지면에서 구조를 뽑는 비전 추출이고, 실패가 곧
오채점으로 이어진다(SC-004: 오채점 0건). 1M 컨텍스트, 128K 출력, 고해상도 비전을 갖췄고
$5 / $25 per MTok로 상위 티어 중 가장 낮다.

**Alternatives considered**:
- `claude-sonnet-5` — 더 싸지만($3/$15) 이 기능의 성패가 추출 정확도 하나로 갈리므로
  비용보다 정확도가 앞선다. **비용 실측 후 재검토 대상**이다
- `claude-fable-5` — 상위 티어이나 $10/$50이고, 30일 데이터 보존이 **필수**다. 미성년자
  데이터를 다루는 이 제품에서 보존 기간이 강제되는 모델은 부적합하다

## D-2. 입력 형식 — 페이지 이미지 (PDF 문서 블록 아님)

**Decision**: 페이지를 PNG로 래스터화해 이미지 블록으로 보낸다. PDF 문서 블록은 쓰지 않는다.

**Rationale**: 세 가지가 같은 결론을 가리킨다.
1. **FR-010이 페이지 단위 전송을 규정한다.** PDF 문서 블록은 파일 전체를 보내므로 전송 범위
   약속을 어긴다
2. **문제집은 필기 합성이 필요하다**(FR-012). 필기는 PDF가 아니라 잉크 스토어에 있으므로
   래스터 합성 외에 방법이 없다
3. 정답지만 PDF 블록을 쓰면 경로가 둘로 갈린다 — FR-011이 "두 PDF가 같은 경로를 타야
   상태·테스트·예외가 한 벌로 유지된다"고 이미 판단했다

**Alternatives considered**: PDF 문서 블록(base64, 32MB·600페이지 한도) — 텍스트 레이어를
모델이 직접 읽어 정확도가 높을 수 있으나 위 세 가지와 전부 충돌한다.

---

## D-3. 렌더 해상도 — 긴 변 2576px

**Decision**: 상한 2576px로 렌더한다.

**Rationale**: Anthropic 고해상도 비전의 긴 변 상한이 2576px다. 그 이상 보내도 서버에서
줄어들 뿐이므로 보낼 이유가 없다. 이 상한에서 이미지당 최대 약 4,784 토큰을 쓴다.
**부수 효과 하나가 중요하다** — 고해상도 경로에서는 모델이 돌려주는 좌표가 실제 이미지
픽셀과 1:1로 대응하므로 배율 보정 계산이 필요 없다(D-6).

**⚠️ 최적값은 미결정.** 2576px가 *상한*이라는 것과 *최적*이라는 것은 다르다. 해상도를 낮추면
토큰이 줄지만 검출 정확도가 어디서부터 무너지는지 모른다 → plan Unresolved.

---

## D-4. 구조화 출력 — `output_config.format` (JSON 스키마)

**Decision**: 응답 자체를 JSON 스키마로 제약한다. 도구 호출(tool use)로 받지 않는다.

**Rationale**: 우리가 원하는 것은 "모델이 도구를 부르는 것"이 아니라 **응답이 곧 데이터인
것**이다. 스키마 강제가 R5(스키마 위반 = 분석 실패)를 API 층에서 대부분 선처리해준다.
동일 스키마는 24시간 컴파일 캐시를 타므로 첫 요청 외에는 추가 지연이 없다.

**⚠️ 스키마 표현력 제약 — 설계에 영향이 있다.** JSON 스키마 지원 범위에
`minimum`/`maximum`/`minLength` 같은 수치·길이 제약이 **없다.** 따라서
`confidence: 0~1`, `label: 1~5` 같은 범위는 스키마로 못 박을 수 없고 **프록시에서 검증**해야
한다. 범위를 벗어난 값은 R5대로 분석 실패로 떨어뜨린다.

**Alternatives considered**: `strict: true` 도구 정의 — 같은 보장을 주지만 응답을 도구 호출로
감싸 한 겹 더 벗겨야 한다. 이득이 없다.

---

## D-5. 프롬프트 캐싱 — 시스템 프롬프트 + 스키마에 브레이크포인트

**Decision**: 시스템 프롬프트 마지막 블록에 `cache_control: {type: "ephemeral"}`를 둔다.
페이지 이미지는 브레이크포인트 **뒤에** 놓는다.

**Rationale**: 캐싱은 접두사 일치다. 한 권을 분석하면 같은 시스템 프롬프트로 수십~수백 번
호출하므로 고정 접두사를 캐싱할 값어치가 크다. `claude-opus-5`의 최소 캐시 길이는
**512 토큰**(이전 세대 1024보다 낮다)이라 프롬프트가 짧아도 걸린다. 캐시 쓰기 1.25배,
읽기 0.1배이므로 **2회차부터 이득**이다.

**지켜야 할 것**: 시스템 프롬프트에 페이지 번호·타임스탬프·문서 ID를 끼워 넣으면 접두사가
매번 달라져 캐시가 통째로 무효화된다. 가변 정보는 전부 이미지 블록 뒤로 보낸다.
`usage.cache_read_input_tokens`가 0에서 안 올라오면 이 규칙이 깨진 것이다.

---

## D-6. 좌표 — 픽셀 그대로 받고 정규화는 우리가

**Decision**: 모델에는 이미지 픽셀 좌표를 요구하고, 정규화는 클라이언트가 한다.

**Rationale**: 고해상도 경로에서 모델 좌표는 실제 픽셀과 1:1이다(D-3). 모델에게 정규화까지
시키면 `MAX_W=760` 규약을 프롬프트에 옮겨 적어야 하는데, 그건 헌법 원칙 IV(규칙의 출처는
하나) 위반이다. 좌표계는 `ARCHITECTURE.md` §5가 유일한 출처이고, 변환은 코드가 참조한다.

---

## D-7. 거부(refusal) 처리 — 서버측 폴백을 기본 탑재

**Decision**: 요청에 `fallbacks: "default"`를 넣는다(베타 `server-side-fallback-2026-07-01`).
그럼에도 거부되면 E5로 처리하고 **자동 재시도하지 않는다.**

**Rationale**: `claude-opus-5`는 안전 분류기가 요청을 거부할 수 있고, 그때 HTTP 200에
`stop_reason: "refusal"`로 돌아온다 — 예외가 아니다. `content[0]`을 무조건 읽는 코드는
거기서 깨진다. 수학 문제집 지면이 거부될 일은 드물지만 오탐이 존재하므로 방어가 필요하다.
폴백을 켜두면 거부가 서버측에서 다른 모델로 회수된다.

**중요**: 같은 입력을 다시 보내도 같은 판정이 나오므로 E5는 재시도 대상이 아니다. E2·E3
(일시적 장애)와 구분해야 한다.

---

## D-8. thinking · effort · max_tokens

**Decision**: `thinking`을 명시하지 않는다(= adaptive). `max_tokens: 16000`.
`effort`는 **기본값 `high`로 시작하고 실측 후 낮춘다.**

**Rationale**: `claude-opus-5`는 thinking이 **기본으로 켜져 있고**, `max_tokens`가
thinking + 응답 텍스트를 **함께** 제한한다. 문항 수십 개짜리 JSON에 16000이면 충분하고
비스트리밍 요청의 타임아웃 여유도 확보된다.

`effort`를 지금 낮춰 박지 않는 이유는 원칙 III다 — 이 워크로드에서 어느 단계가 충분한지
측정한 적이 없다. `low`/`medium`이 예상보다 강하다고 알려져 있으므로 **비용 실측 때 함께
스윕**한다(plan Unresolved의 비용 항목과 같은 측정에 묶는다).

---

## D-9. 프록시 서버

**Decision**: `apps/proxy` 신규. 단일 엔드포인트 `POST /analyze`. **프롬프트와 스키마를
프록시가 소유한다.**

**Rationale**: 헌법 원칙 I이 API 키의 클라이언트 포함을 금지한다. 프롬프트까지 프록시에 두는
것은 추가 판단이다 — 클라이언트에 두면 번들에서 읽어 임의 프롬프트로 우회할 수 있고, 그러면
R6(AI는 판정하지 않는다)을 클라이언트가 무력화할 수 있다.

프록시는 **중계만 하고 학생 데이터를 영속 저장하지 않는다**(헌법 「데이터와 프라이버시」).

**⚠️ 배포 형태 미결정** — 서버리스/상시 서버 판단은 지연·동시성 실측 뒤로 (plan Unresolved).

---

## D-10. 토큰·비용 기준선 측정 방법

**Decision**: `client.messages.countTokens`로 실측한다. 추정 라이브러리를 쓰지 않는다.

**Rationale**: `tiktoken` 류는 OpenAI 토크나이저라 Claude 토큰을 15~20% 과소 계산한다.
plan의 비용 상한 미결정을 해소하려면 정확한 기준선이 필요하고, 그 수단은 이 API뿐이다.

**측정 대상**: 골든 5권의 대표 페이지에 대해 (a) 해상도별 이미지 토큰, (b) effort별 출력
토큰, (c) 캐시 적중률. 이 셋이 plan Unresolved의 **비용·해상도·effort 세 항목을 한 번에**
해소한다.
