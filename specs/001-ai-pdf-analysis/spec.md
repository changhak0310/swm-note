# Feature Specification: AI 기반 PDF 문항 분석

**Feature Branch**: `feat/auto-scoring` (전용 브랜치 없음)

**Created**: 2026-07-30

**Status**: Draft — 미해결 0건 (Q1~Q3 해소 2026-07-30)

**Input**: User description: "그래서 지금은 ai 연동해서 pdf 분석 기능이 필요해. 지금 mvp는 ai를 통해 pdf분석 기능을 추가 하고 싶어"

## 문제

자동 채점이 안 되는 원인은 **채점이 아니라 분석**이다.

판정 기하는 이미 상한 **100.00%** 다 (선지 2958개 실측, `research/객관식_인식.md` §11.11). 즉
"어느 선지에 마크했는가"는 풀린 문제다. 무너지는 곳은 그 앞이다 — **문제집마다 조판이 달라서
문항 번호·문항 영역·선지 위치를 찾아내지 못한다.**

- 검출은 10단 게이트다. 각 단이 1%씩만 틀려도 생존율이 `0.99¹⁰ ≈ 90%` 이고, 실측 실패율은
  그보다 훨씬 나쁘다 (`research` §7)
- 스캔본 경로는 **설계상 문제 번호의 값을 읽지 않는다**(`lib/scan/detect.ts`). 그래서 정답지
  대조 재현율이 0%로 나온다 — 검출 실패가 아니라 **잣대가 없는 것**이다 (`research` §11.13)
- 텍스트 레이어 경로도 책을 타는데, "수학의 신"에서는 검출 번호의 90%가 중복이었다 (`research` §9.3)

학생 입장에서 이것은 **"어떤 문제집은 채점이 아예 안 된다"** 로 나타난다.

## 대상

대한민국 고1~3 수능 수학 학습자. 안드로이드 태블릿 + 스타일러스 펜 사용자. 본인이 소유한
문제집 PDF와 그 정답지 PDF를 앱에 올려 푼다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 낯선 조판의 문제집도 채점된다 (Priority: P1)

학생으로서, **처음 올리는 문제집도 문항이 제대로 잡히길** 원한다. 지금은 책에 따라 검출이
무너져서 그 책 전체를 채점에 쓸 수 없기 때문이다.

**Why this priority**: 이게 안 되면 나머지가 전부 무의미하다. 앱의 진입 장벽 그 자체다.

**Independent Test**: 기존 파이프라인이 실패하는 것으로 알려진 문제집(수학의 신)을 올려서,
문항 번호·영역·선지가 골든 라벨과 일치하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 기존 경로가 검출에 실패하는 문제집 PDF, **When** 학생이 문제집을 등록하면,
   **Then** 문항 번호·문항 영역·선지 위치가 추출되어 채점에 사용할 수 있다
2. **Given** 분석이 끝난 문제집, **When** 학생이 같은 문제집을 다시 열면, **Then** 재분석 없이
   저장된 결과를 쓴다
3. **Given** 외부 전송에 동의하지 않은 학생, **When** 문제집을 등록하면, **Then** 무엇이
   전송되는지 항목으로 안내받고, 거부해도 기존 로컬 분석 경로로 등록이 진행된다

---

### User Story 2 - 스캔한 문제집도 정답 대조가 된다 (Priority: P2)

학생으로서, **사진으로 찍거나 스캔한 문제집도 정답과 대조되길** 원한다. 지금 스캔 경로는 문제
번호의 값을 읽지 않아 정답지와 짝지을 수 없기 때문이다.

**Why this priority**: 종이 문제집을 쓰는 학생이 다수다. 다만 P1이 풀리면 텍스트 PDF만으로도
제품이 성립하므로 그다음이다.

**Independent Test**: 스캔 PDF 1권을 올려 문항 번호 값이 읽히고 정답지 항목과 짝지어지는지
확인한다.

**Acceptance Scenarios**:

1. **Given** 스캔 이미지 PDF, **When** 분석이 끝나면, **Then** 각 문항에 번호 **값**이 붙어
   정답지 항목과 대조된다

---

### User Story 3 - 분석이 틀리면 학생이 안다 (Priority: P3)

학생으로서, **분석이 잘못됐을 때 그것을 알고 고칠 수 있길** 원한다. 잘못된 분석이 조용히
오채점으로 이어지면 앱을 믿을 수 없기 때문이다.

**Why this priority**: 신뢰 문제라 중요하지만, P1·P2가 없으면 고칠 대상 자체가 없다.

**Acceptance Scenarios**:

1. **Given** 신뢰도가 낮은 분석 결과, **When** 채점을 시도하면, **Then** 오답으로 단정하지 않고
   확인을 요청한다
2. **Given** 잘못 잡힌 문항 영역, **When** 학생이 수정하면, **Then** 수정 결과가 저장되어 이후
   채점에 쓰인다

### Edge Cases

- 문제집 PDF의 **일부 페이지만** 분석에 실패하면? (책 전체를 버리지 않고 페이지 단위로 처리)
- 분석 도중 **네트워크가 끊기면**? (부분 결과를 버릴지 이어갈지)
- 같은 문제집을 **두 번 등록**하면? (재분석 비용이 또 드는지)
- 정답지와 문제집의 **문항 수가 다르면**? (해설 페이지, 부록 등)
- 문제집에 **객관식이 아닌 문항**이 섞여 있으면? (현재 채점 대상은 `choice`뿐)
- 분석 결과가 **명백히 이상하면**? (예: 한 페이지에 문항 200개)
- **필기가 선지나 문제 번호를 가리면?** 문제집 페이지는 필기가 얹힌 뒤에 전송되므로(FR-010),
  학생의 풀이가 조판을 덮어 구조 검출을 방해할 수 있다
- 학생이 **오프라인에서 푼 페이지**는 언제 분석되나? (연결 시점까지 미판정으로 남는 기간)
- 학생이 **필기를 지웠다가 다시 쓰면?** 같은 페이지를 다시 전송할지, 첫 전송분을 쓸지

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 문제집 PDF에서 문항 번호 값, 문항 영역, 선지 위치를 추출해야 한다
- **FR-002**: 시스템은 추출 결과를 **페이지 단위로** 기기에 저장하고, 같은 페이지를 다시 열 때
  재분석하지 않아야 한다
- **FR-003**: **이미 분석이 끝난** 문항의 채점은 네트워크 없이 완전히 동작해야 한다. 아직
  분석되지 않은 문항은 오답으로 단정하지 않고 **대기 상태**로 남기며, 연결된 뒤 이어서 처리해야
  한다. 네트워크가 없어도 학생의 필기·풀이는 막히지 않아야 한다
- **FR-004**: 시스템은 추출 결과의 신뢰도를 학생에게 드러내야 하며, 신뢰도가 낮은 문항은
  정답/오답으로 단정하지 않고 미판정으로 남겨야 한다
- **FR-005**: 학생은 잘못 잡힌 문항 번호·영역·선지를 직접 수정할 수 있어야 하고, 수정 결과가
  이후 채점에 반영되어야 한다
- **FR-006**: 시스템은 기기 밖으로 나가는 데이터 항목을 학생에게 열거해 보여주고 명시적 동의를
  받아야 하며, 동의를 거부해도 기존 로컬 분석 경로로 앱을 계속 쓸 수 있어야 한다
- **FR-007**: 검증되지 않은 분석 결과가 채점에 쓰여서는 안 된다 — 형식이 깨진 결과는 분석
  실패로 처리한다
- **FR-008**: 분석 실패는 페이지 단위로 격리되어야 한다. 일부 페이지의 실패가 문제집 전체를
  사용 불가로 만들어서는 안 된다
- **FR-009**: 문항 구조 분석은 **AI가 단독으로** 수행한다. 기존 로컬 파이프라인
  (`lib/psp/` 3,088줄 · `lib/scan/` 1,778줄)은 **삭제하지 않되 이번 범위에서 호출하지
  않는다** — 폴백 경로를 짜는 데 드는 시간이 이번 목표(학습·MVP·개발 속도)와 맞지 않는다.
  로컬 1차 + AI 폴백 구조는 정확도·비용 실측 이후로 미룬다
- **FR-010**: 기기 밖으로 나가는 것은 **페이지 단위**이며, 다음 두 가지뿐이다.
  - **정답지** — 정답지 PDF의 페이지 전체
  - **문제집** — **필기가 입력된 페이지**의 전체. 필기가 없는 페이지는 전송하지 않는다

  원본 PDF 파일 전체, 학생 식별 정보, 채점 이력은 전송하지 않아야 한다
- **FR-011**: 문제집 PDF와 정답지 PDF **둘 다** AI 분석 대상이다
- **FR-012**: 문제집 페이지는 **학생 필기가 포함된 상태로** 전송된다. 시스템은 이 사실을 동의
  화면에 명시해야 하며(MUST), 필기가 함께 나간다는 점을 흐리거나 생략해서는 안 된다
- **FR-013**: AI는 문항 구조와 정답만 추출한다. 필기가 포함된 페이지를 보더라도 정답/오답
  판정을 만들어서는 안 된다 — 마킹 판정은 로컬 기하가 단독으로 내린다

### Key Entities

- **문제집 분석 결과**: 한 문제집 PDF에 대해 한 번 만들어지는 문항 구조. 문항별 번호 값, 영역,
  선지 위치, 신뢰도, 출처(어느 경로가 만들었는지)를 담는다. 기기에 저장된다.
- **문항(Region)** · **정답 항목(AnswerEntry)**: `ARCHITECTURE.md` §4에 이미 정의돼 있다.
  여기서 다시 정의하지 않는다.
- **전송 동의 기록**: 학생이 무엇의 외부 전송에 동의했는지와 그 시점.

## Out of Scope *(mandatory)*

| 제외 | 이유 |
|---|---|
| 필기 인식 · AI 오답 원인 진단 | 별개 기능이다. 채점이 먼저 서야 그 위에 원인 진단이 얹힌다 |
| 주관식·서술형 채점 | `ROADMAP.md` §11 2차 이월. 현재 채점 대상은 `answerType: 'choice'` 뿐이다 |
| 사용자 간 정답지·분석 결과 공유 | 헌법 원칙 I 위반. 학생 데이터의 저장소는 기기다 |
| **AI를 검증(verify) 단계에 쓰기** | `lib/psp/verify.ts` §6.1이 이미 명시적으로 거부했다 — *"LLM은 '몇 점'만 줄 뿐 '무엇이 틀렸는지'를 못 알려주므로 검수 UI에 연결할 수 없다."* 검증은 결정론으로 남긴다 |
| AI가 정답/오답 판정을 내리는 것 | 헌법 원칙 II. 판정은 결정론적 도구가, AI는 분석까지만 |
| 기존 `lib/psp/` · `lib/scan/` 삭제 | 지우지 않는다. **이번 범위에서 호출하지 않을 뿐**이다. 삭제는 AI 경로의 정확도가 실측된 뒤에 판단한다 |
| 로컬 1차 + AI 폴백 오케스트레이션 | 개발 속도 우선. 전환 임계값을 정하려면 골든 5권 실측이 선행돼야 하는데, 그 측정 자체가 이번 목표보다 오래 걸린다 |
| 필기 수정 시 재분석 | 한 페이지 1회 전송을 가정한다(Assumptions). 재전송 정책은 비용 상한이 정해진 뒤에 다룬다 |
| 골든 라벨 데이터셋 구축 | `research` §11에서 진행 중인 별도 작업이다 |

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 골든 데이터셋 5권 기준 문항 검출 재현율 **99% 이상**
  (근거: `research` §11.1 — *"골든 데이터셋을 주면 그 상태가 나오고 최종 정확률 99% 이상"*)
- **SC-002**: 기존 경로가 실패하던 문제집(수학의 신)에서 문항 번호 **중복률 0%**
  (근거: `research` §9.3 — 현재 검출 번호의 90%가 중복)
- **SC-003**: 스캔 PDF의 정답지 대조 재현율이 0% → **99% 이상**
  (근거: `research` §11.13 — 현재 스캔 경로는 번호 값을 읽지 않아 0%)
- **SC-004**: **오채점 0건.** 분석이 불확실한 문항은 틀린 판정 대신 미판정으로 남는다
  (근거: 헌법 원칙 II — 한 번의 오채점이 여러 번의 정채점보다 신뢰를 빨리 무너뜨린다)
- **SC-005**: 이미 분석이 끝난 문항의 채점이 비행기 모드에서 **100% 동작**한다
  (근거: 헌법 원칙 I — 채점과 오답노트는 네트워크 없이 완전히 동작해야 한다)

## Assumptions

- **이번 범위의 목표는 학습과 MVP 검증이며, 개발 속도가 정확도 최적화·비용 절감보다 앞선다.**
  이 가정이 바뀌면 FR-009(AI 단독)가 가장 먼저 재검토 대상이다 — 로컬 1차 구조로 되돌린다.
- 학생은 본인이 소유한 문제집·정답지를 올린다. 앱이 콘텐츠를 배포하지 않는다.
- **분석 시점은 둘로 나뉜다.** 정답지는 등록 시, 문제집 페이지는 그 페이지에 필기가 처음 생긴
  시점이다. 학생이 끝내 안 푼 페이지는 분석하지 않는다 — 비용이 실제로 푼 분량에만 붙는다.
- 한 페이지는 원칙적으로 **한 번만** 전송된다. 이 가정이 깨지면(예: 필기 수정 시마다 재전송)
  비용 구조가 무너진다.
- 프록시 서버가 존재한다. 헌법 원칙 I이 API 키의 클라이언트 포함을 금지하므로 **프록시 서버는
  이 기능의 선행 조건이며, 현재 존재하지 않는다.**
- 판정 기하는 손대지 않는다. 이미 상한 100.00%이므로 이 기능의 성패는 분석 정확도로만 갈린다.

## 헌법 정합

**충돌은 해소됐다 — 헌법 v3.0.0 개정(2026-07-30).**

원래 원칙 I은 *"채점과 오답노트는 네트워크 없이 완전히 동작해야 한다. AI는 그 위에 얹히는
선택적 계층이다"* 였다. AI가 분석을 단독 수행하면(FR-009) AI는 더 이상 선택적 계층이 아니므로
이 문구와 충돌했다. 헌법을 사실에 맞게 개정하는 쪽(A안)을 택했다.

**개정 후 원칙 I — 「로컬 저장 · AI 기능은 네트워크 필수」**

| 규칙 | 이 스펙의 대응 |
|---|---|
| AI 호출이 필요한 기능은 네트워크 연결을 요구한다 | FR-009 |
| 연결이 없으면 실패가 아니라 **대기 상태**로 남고, 연결 후 이어서 처리한다 | FR-003 |
| 네트워크 부재가 학생의 필기·풀이를 막아서는 안 된다 | FR-003 |
| **이미 분석된** 문항의 채점·오답노트 열람은 오프라인에서 완전히 동작한다 | FR-002 · SC-005 |
| AI 호출은 프록시 경유, API 키 클라이언트 포함 금지 | Assumptions (선행 조건) |

개정에서 **완화하지 않은 선 셋**이 그대로 이 스펙의 제약이다 — 저장은 로컬, 한 번 분석된 것은
오프라인, 필기는 언제나 가능.

`/speckit-plan`의 `Constitution Check` 게이트를 막던 사유가 사라졌다.

## Open Questions

- **로컬 1차 + AI 폴백을 언제 도입하나.** 이번엔 뺐지만(Out of Scope) 영구 폐기는 아니다.
  `lib/psp/verify.ts`가 이미 신뢰도 점수를 내므로, 골든 5권에서 분포를 측정하면 전환 임계값을
  정할 수 있다. 그 측정을 언제 할지가 미정이다.
- **페이지당 허용 대기 시간과 비용 상한이 정해지지 않았다.** 실측 없이 정할 수 없어 헌법
  원칙 III에 따라 지어내지 않는다. 시제품으로 1권을 돌려본 뒤 정한다.
- **필기가 조판을 가리는 정도가 측정된 적 없다.** 문제집 페이지를 필기 이후에 보내는 설계라
  (FR-010) 검출 정확도에 영향이 있는데, 얼마나 나빠지는지 모른다. 필기 전/후 같은 페이지를
  비교 측정하면 답이 나온다.
- **부분 실패 시 재시도 정책이 미정.** 페이지 단위 격리(FR-008)까지는 정했으나, 실패한 페이지를
  언제·몇 번 다시 시도할지는 비용 상한이 정해져야 결정할 수 있다.
- **동의를 거부한 학생의 경험이 어디까지 열화되는지 측정된 적 없다.** 기존 로컬 경로로
  폴백한다는 것까지만 정했다(FR-006). 그 경로의 실제 성공률이 곧 "거부 시 품질"이다.
- **신뢰도를 학생에게 어떤 형태로 보여줄지 미정.** 화면 소관이라 plan 단계로 넘긴다.
